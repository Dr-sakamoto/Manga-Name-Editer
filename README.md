# Manga-Name-Editer

漫画のネーム（構成）を **ページ占有率** と **フリ・オチのネットワーク** で管理するツールです。

思いついたシーンに「これは1ページ2コマの決めゴマだから200%」といったページ占有率を与えて並べていくと、
残ページが自動で可視化され、シーンの分割・並べ替えでページ配置が組み替わります。
同時に、各シーンが読者の頭に生む「予測」と、それを回収するシーンの網の目を管理・可視化できます。

ブラウザだけで動きます（サーバー不要・データはブラウザに自動保存）。

## できること

### 1. ページ占有率でシーンを積む

- シーンごとに占有率(%)を登録：**100% = 1ページ**、200% = 2ページ、50% = 半ページ
- ヘッダーの帯で「使用 / 残り」を常時表示。総ページを超えると赤で警告
- 種別（シーン・見せ場・情感・説明・ギャグ・空き）で色分け。説明コマが全体の何割かも集計

### 2. 残ページの可視化とページ割り（パズル）

- 「ページ割り」タブは見開き単位のページマップ（右綴じ。右のページが先）
- ページを跨ぐシーンは自動で分割表示（`↳` が前ページからの続き）
- 空きページは斜線で表示。**ブロックをドラッグして別のページに放り込むと、後ろのシーンが自動でずれます**
- 意図的に空けておきたい場所には「空きを挿入」でスペーサーを置けます

### 3. シーンの分割（あとから具体化）

ざっくり登録した塊を、あとから細かいシーンに割っていけます。

```
敵を倒す 200%
 └ 構える        50%
 └ 引き金をひく   50%
 └ うつ         100%
```

- 分割前の占有率は「想定」として残り、子の合計とズレたら差分を警告
- 子シーンをさらに分割することもできます（何段でも）
- ドラッグの「真ん中」に落とす操作でも、シーンを別のシーンの中に入れて具体化できます

### 4. フリ・オチのネットワーク

漫画で実際に起こること（シーン）と、それによって読者の脳内に生まれる予測・期待・疑問（**予測＝スレッド**）を
別々に持ち、両者を多対多で繋ぎます。

シーンから予測への接続は4種類：

| 役割 | 意味 |
| --- | --- |
| フリ（立てる） | このシーンが読者の予測を新しく生む |
| 強化（積む） | 既にある予測をさらに濃くする |
| ねじれ（裏切る） | 予測を裏切って別の形に変える（回収はしない） |
| オチ（回収） | この予測に答えを出して閉じる |

1つのシーンが複数の予測を立て、1つのシーンが複数の予測を同時に回収し、
その回収と同時にまた新しい予測が生まれる——という直列でない網の目をそのまま表現できます。

```
尾行 ──フリ──▶「こいつは敵なのでは？」──オチ──▶ 助ける
  └──フリ──▶「主人公は何かを隠している」──強化──▶ 助ける
助ける ──(回収と同時)──▶ 盗む ──フリ──▶「本当の目的は何だ？」
```

「フリ・オチ」タブでは、これを横軸＝ページ位置のレーン図で可視化します。

- 横棒＝フリからオチまでの引っぱり。点線＝まだ回収されていない
- 丸＝フリ / 四角＝強化 / 三角＝ねじれ / 菱形＝オチ
- 曲線の矢印＝回収（またはねじれ）と同時に生まれた新しい予測の派生
- 下の棒グラフ＝そのページで読者が同時に抱えている予測の数（＝認知の負荷）

シーンを選ぶと「ここまでに立っていて、まだ回収されていない予測」が並ぶので、
ワンクリックで「このシーンで回収」「ここで強化」を繋げます。

### 5. 見直し

- 総ページの超過／残り
- 分割の合計が分割前の想定とズレているシーン
- 未回収の予測、フリのない予測、オチがフリより前に来ている矛盾
- 説明コマの比率、いちばん長い引っぱり、読者の認知負荷のピーク

## 使い方

```bash
npm install
npm run dev      # 開発サーバー
npm run build    # dist/ に本番ビルド
npm run test     # ロジックのテスト
```

`npm run build:single` で、`dist-single/index.html` に1ファイル完結のHTMLを書き出せます
（ファイルをブラウザで開くだけで動きます）。

### 保存とバックアップ

編集内容はブラウザの localStorage に自動保存されます。
ヘッダーの「データ」から JSON を書き出し／読み込みできるので、
バックアップや別端末への持ち出し、ネームの複製に使ってください。

### ショートカット

| キー | 動作 |
| --- | --- |
| ドラッグ（上下端） | そのシーンの前／後ろに挿入 |
| ドラッグ（真ん中） | そのシーンの中に入れて具体化 |
| `Alt` + `↑` `↓` | シーンを前後に移動 |
| `Alt` + `→` `←` | 階層を下げる／上げる |
| `Ctrl/⌘` + `Z` | 元に戻す |
| `Ctrl/⌘` + `Shift` + `Z` | やり直す |

## データの形

```ts
Scene  { id, parentId, title, ratio, event, note, kind }   // 起こること
Thread { id, label, kind, color, note }                    // 読者の頭に生まれる予測
Link   { id, sceneId, threadId, role, note }               // 両者の接続（多対多）
```

シーンは `parentId` による木構造、表示順は配列順。
ページ位置は葉シーンの占有率を先頭から積み上げて計算するので、
並べ替えれば後続のページ配置がすべて追従します。

## 構成

```
src/
  lib/
    types.ts     データ定義
    layout.ts    ページ計算・並べ替え・分割・フリオチ解析（テスト対象）

    api.ts       画面から呼ぶ操作
    sample.ts    サンプルネーム
  components/
    SceneBoard.tsx     シーン一覧（ドラッグ＆ドロップ）
    SplitDialog.tsx    分割ダイアログ
    PageMap.tsx        見開きページマップ
    ThreadNetwork.tsx  フリ・オチのレーン図
    ThreadPanel.tsx    予測の一覧
    Inspector.tsx      シーン／予測の編集
    Warnings.tsx       見直し
```
